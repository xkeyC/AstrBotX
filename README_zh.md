AstrBot 是一个开源的一站式 Agent 聊天机器人平台，可接入主流即时通讯应用，为个人、开发者和团队提供可靠、可扩展的对话式 AI 基础设施。无论你要构建个人 AI 伙伴、智能客服、自动化助手还是企业知识库，AstrBot 都能帮助你在即时通讯平台的工作流中快速构建可用于生产环境的 AI 应用。

![screenshot_1 5x_postspark_2026-02-27_22-37-45](https://github.com/user-attachments/assets/f17cdb90-52d7-4773-be2e-ff64b566af6b)

## Codex 原生 Agent 运行时

本分支把 AstrBot 的 Agent 循环换成了同进程运行的
[OpenAI Codex](https://github.com/openai/codex)，通过 pyo3 绑定
（[xkeyC/codex_for_astrbot](https://github.com/xkeyC/codex_for_astrbot)）嵌入。AstrBot
保留它擅长的部分——平台适配、消息管线、插件、人格、WebUI——由 Codex 负责 Agent 编排。
这里 `codex` 是唯一的 Agent 运行器，原有的 `local`、Dify、Coze、DashScope、DeerFlow
运行器配置会自动迁移过来（迁移前的文件保存为 `*.pre-codex.json`）。

绑定是硬依赖且**从源码构建**，安装本分支需要 Rust 工具链（见[安装本分支](#安装本分支)）。

### 模型与提供商

模型、模型提供商、推理强度和提示词在 WebUI 的 **Codex** 页面设置：登录 ChatGPT 账号或填写
API Key，也可以添加 OpenAI 兼容的提供商。提供商可以走 Responses API；只支持 Chat Completions
的第三方服务走 chat wire。每个提供商还可以设置额外的请求头和请求体字段、压缩方式（自动 / 本地 /
远程）以及模型元数据（上下文窗口、自动压缩阈值、推理档位、是否支持图片输入）。模型提供商页面
不再配置 AstrBot 自己的对话模型：插件的 LLM 调用由 Codex 应答，除非插件指定了配置里仍然存在的
对话模型提供商。

### Code mode

每一轮都跑在 Codex 的 code mode（`model_tool_mode = code_mode_only`）下：提示词里只声明
`exec` 和 `wait`，模型通过写 JavaScript 在独立的 V8 宿主进程里调用 AstrBot 的工具。插件、
MCP 和内置工具都注册为延迟加载的动态工具，它们的 schema 完全不进入提示词前缀。

| 场景 | AstrBot 本地运行器 | Codex（code mode） |
| --- | --- | --- |
| 5 个工具，估算 token | 81.1k | 45.6k（**-44%**） |
| 45 个工具，估算 token | 234.4k | 45.6k（**-81%**） |

Codex 的提示词开销不随工具数量增长，一串相互依赖的调用也合并成一次 `exec` 往返，而不是每次调用
一个回合。按发送者过滤工具也没有额外开销：对某人隐藏工具不会改动已缓存的前缀。

### 按发送者的权限规则

`permission_rules`（WebUI：**权限规则**）取代了 DynamicPersona 插件。每条规则匹配发送者
（`<群>/<发送者>`、`p_<发送者>`、`g_<群>`、`role:admin`、`*`），可以设置人格和模型、允许或禁止
工具和 MCP 服务、授予全局记忆写入权限，以及限制请求频率和定时任务。被禁止的工具在调用时会被
拒绝，在 code mode 下也不会出现在模型可见的工具集合里。

### 执行环境

Codex 自己的 shell 已关闭：执行工具由 AstrBot 提供，由“使用电脑能力”的运行环境
（`provider_settings.computer_use_runtime`，唯一的执行开关）执行。

- `exec_command` / `write_stdin`——Codex 模型训练时用的这一对工具，背后是 tmux PTY 会话，需要
  确认或打开 REPL 的命令会像人操作时一样运行。没跑完的会话会在后台轮询到结束，结果再发回聊天。
- `apply_patch`——Codex 原生的补丁格式。
- `local` 运行环境——命令和文件修改遵守角色的本地权限策略（文件范围、执行、网络；需要时用
  bubblewrap / Seatbelt 隔离）。
- `sandbox` 运行环境——所有 Agent 文件操作都在
  [Shipyard Neo](https://github.com/AstrBotDevs/astrbot-shipyard-neo) 沙盒内完成，包括 Skills，
  不会碰宿主机文件系统。

网页搜索使用 Codex 自己的联网搜索（**Codex** 页面）；AstrBot 内置的网页搜索提供商已移除。

### 记忆

Codex 的原生记忆按会话隔离。每个会话有自己的私有存储；只有当提取模型判断某条记忆不涉及个人信息，
**并且**发送者的规则授予了 `global_memory`（群聊从不授予）时，才会提升到共享的全局存储。定期整理
作为 Codex 子 Agent 在记忆目录上运行；能写全局记忆的人也能删除，错误的记忆可以撤回。

### 并发

一个会话就是一个 Codex 线程，同一时间只跑一轮。正在运行那一轮的发送者追加的消息会被 steer 进去，
在同一条回复里回答；其他人的消息在后面排队，最多 `max_queued_turns` 条。

### 实时语音

Mumble 频道（内置适配器）、QQ 通话（[qq-voice-call](https://github.com/xkeyC/astrbot-qq-voice-call)
插件配合 NapCat 桥接）和 VRChat 房间（插件）都可以和机器人语音对话。语音后端在 **Codex** 页面选择：
Codex 内置实时语音（OpenAI realtime 模型），或本地多模态服务（VAD、语音识别、唤醒词、语音合成）
加上由 Codex 模型负责对话。每个语音通话与对应会话配对：较长的任务交给会话线程处理，通话记录只保存
模型实际听到的内容。

### 本地多模态服务（local-multimodal-infra）

[local-multimodal-infra](https://github.com/mercallureAI/local-multimodal-infra) 是一级服务：
**模型提供商 → 本地多模态服务**保存它的地址和令牌，列出服务器上的模型，并按服务器上的启用状态为每项
服务选用模型——语音识别、语音合成、嵌入、重排序、内容审核和实时语音，每项都可以单独关闭。前四项作为
提供商 `local_infra/…` 出现在各处的提供商选择中（自动选用的嵌入模型会被固定，知识库始终使用同一个
模型）。插件通过 `Context.get_local_infra()`（或 `astrbot.api.local_infra`）调用同一个服务：
`synthesize`、`transcribe`、`embed`、`rerank`、`moderate`、`ocr_lines`、`detect_objects` 以及通用的
`run_task`。

### 内容审核

开启本地多模态服务的内容审核后，发给云端模型的内容会先经过审核：用户消息及其中的图片、群聊上下文
（只去掉违规的那几条，不拒绝整个请求）、工具结果（只去掉违规的部分），以及语音通话听到的内容。每个
平台实例可以选择开启、仅文本或关闭。

### 遥测

只要登录了账号，Codex 就会向 `chatgpt.com` 上报 Skill 调用、MCP 调用和线程元数据。本分支固定
`analytics.enabled = false` 和 `otel.metrics_exporter = "none"`，因为聊天机器人运行的是别人的对话。
可以通过 `thread_config` 重新打开。请求以 `codex_exec` 身份发出，User-Agent 带
`xkeyC/codex_for_astrbot` 标记。

## 与上游的行为差异

本分支在以下方面有意与上游 AstrBot 不同：

1. 因 Codex 已覆盖而移除：子代理编排、AstrBot 内置的网页搜索提供商、第三方 Agent 运行器、Python
   执行工具、按会话覆盖对话模型以及 `/provider` 切换对话模型（`/provider` 只处理 TTS / STT）。只被
   已移除运行器读取的设置会在加载或保存配置时丢弃。
2. 对话模型调用在内部一律走流式，即使调用方使用非流式接口。
3. Docker 和 git/wheel 安装会构建并优先使用本仓库自带的 dashboard，而不是同版本号的上游
   `data/dist`。
4. MCP 服务连接测试会使用配置的代理。
5. WebUI 人格管理支持克隆人格。
6. 插件可以通过 `AstrMessageEvent.set_llm_overrides()` 为单次请求指定人格 / 提供商 / 模型，不改动会话
   配置；会话强制绑定的人格仍优先于事件级的人格覆盖。
7. Shipyard Neo 自动启动模式会把 AstrBot 的全局代理设置传给托管的 Bay 容器，代理变化时重建容器，
   新的沙盒 Python / Shell 会话随之使用新代理。
8. 人格的工具白名单覆盖模型能调用的所有工具，当前人格不允许的调用即使由模型手工构造也会被拒绝。
9. 经 NapCatQQ 接入的 OneBot v11 可以先给要回复的消息贴一个表情
   （`platform_specific.aiocqhttp.pre_ack_emoji`，仅群聊）。

这些改动由本分支维护，可能与上游行为不一致。

## 主要功能

1. 💯 免费 & 开源。
2. ✨ AI 大模型对话，多模态，Agent，MCP，Skills，知识库，人格设定，自动压缩对话。
3. 🤖 以 Codex 为 Agent 运行时：code mode、按发送者的权限规则、按会话隔离的记忆、实时语音。
4. 🌐 多平台，支持 QQ、企业微信、飞书、钉钉、微信公众号、Telegram、Slack 以及[更多](#支持的消息平台)。

6. 🛡️ [Agent Sandbox](https://docs.astrbot.app/use/astrbot-agent-sandbox.html) 隔离化环境，安全地执行任何代码、调用 Shell、会话级资源复用。
7. 💻 WebUI 支持。
8. 🌈 Web ChatUI 支持，ChatUI 内置 Agent 沙盒和 Codex 联网搜索。
9. 🌐 国际化（i18n）支持。

## 快速开始

### 安装本分支

下面的部署方式安装的是上游 AstrBot。要安装本分支，需要指向对应分支，并确保环境里有 Rust
工具链——Codex 绑定是从源码构建的：

```bash
pip install "astrbot @ git+https://github.com/xkeyC/AstrBotX@codex_agent_runtime"
```

首次安装会编译整个 Rust 工作区，并为 code-mode 宿主下载预编译的 V8，耗时较长；之后安装
同一个 commit 会复用 pip 的 wheel 缓存。绑定在 `pyproject.toml` 中固定到某个 commit，构建选项见
[绑定的 README](https://github.com/xkeyC/codex_for_astrbot/tree/astrbot/codex-rs/astrbot-py)。
安装后在 WebUI 的 **Codex** 页面登录或添加模型提供商。

### 在雨云上一键部署

对于希望一键部署并让 AstrBot 24 小时在线、且不想自行管理服务器的用户，我们推荐使用雨云的一键云部署服务 ☁️：

[![Deploy on RainYun](https://rainyun-apps.cn-nb1.rains3.com/materials/deploy-on-rainyun-en.svg)](https://app.rainyun.com/apps/rca/store/5994?ref=NjU1ODg0)

### 一键部署

> [!NOTE]
> 需要安装 [uv](https://docs.astral.sh/uv/)。
> 对于 macOS 用户：由于 macOS 安全检查，首次运行 `astrbot` 命令可能需要较长时间（约 10-20 秒）。

对于想快速体验 AstrBot、且熟悉命令行并能够自行安装 `uv` 环境的用户，我们推荐使用 `uv` 一键部署方式 ⚡️。

```bash
uv tool install astrbot --python 3.12
astrbot init # 仅首次执行此命令以初始化环境
astrbot run
```

后续更新 `astrbot`：

```bash
uv tool upgrade astrbot --python 3.12
```

### Docker 部署

对于熟悉容器、希望获得更稳定且更适合生产环境部署方式的用户，我们推荐使用 Docker / Docker Compose 部署 AstrBot。

请参考官方文档 [使用 Docker 部署 AstrBot](https://docs.astrbot.app/deploy/astrbot/docker.html#%E4%BD%BF%E7%94%A8-docker-%E9%83%A8%E7%BD%B2-astrbot)。

### 桌面客户端部署

对于希望在桌面端使用 AstrBot、并以 ChatUI 为主要入口的用户，我们推荐使用 AstrBot App。

前往 [AstrBot-desktop](https://github.com/AstrBotDevs/AstrBot-desktop) 下载并安装；该方式面向桌面使用，不推荐服务器场景。

### 启动器部署

同样在桌面端，希望快速部署并实现环境隔离多开的用户，我们推荐使用 AstrBot Launcher。

前往 [AstrBot Launcher](https://github.com/Raven95676/astrbot-launcher) 下载并安装。

# 内容审核

开启后，AstrBot 在把内容交给云端模型（Codex）之前，先用一个兼容 OpenAI 审核接口（`POST /v1/moderations`）的服务检查一遍，例如 [local-multimodal-infra](https://github.com/xkeyC/local-multimodal-infra) 的本地审核服务（Qwen3Guard 文字模型、NSFW 图片分类器、图中文字识别）。被判违规的内容不会发给模型，用于避免模型服务商的警告或封号。

## 开启

1. 在 `设置` → `安全` → `内容审核` 中填写 **内容审核服务地址**，例如 `http://127.0.0.1:17890`。留空即不审核。服务开启了密钥保护时，再填写 **内容审核服务密钥**（以 `Authorization: Bearer <密钥>` 发送）。
2. 在 `平台` 中编辑每个机器人，设置 **内容审核**：
   - `开启`：审核文字和图片（默认）；
   - `仅文本`：只审核文字，图片不审核；
   - `关闭`：不审核。

## 审核哪些内容

| 内容 | 违规时 |
| --- | --- |
| 用户发来的消息：文字、图片、以文件发送的图片、引用的消息 | 整条消息不交给模型，回复拦截提示语（默认「这条内容无法处理。」，可在设置中修改） |
| 群聊上下文（之前的群消息） | 只去掉违规的那几条，其余照常带上 |
| `get_group_message_history` 工具读出的群消息记录 | 同上，只去掉违规的那几条 |
| 工具结果：读文件、读图片、网页 / MCP / 插件工具、沙箱输出、后台任务和后台命令的结果 | 只去掉违规的文字段或图片，并告诉模型去掉了什么、属于哪类 |
| 插件自己的模型调用、群图片转述 | 调用失败（插件拿到错误结果），图片转述不生成 |

AstrBot 自己附加的上下文（发送者元信息、知识库检索结果）不属于用户消息，不审核。日志中只记录违规类别，不记录原文。

### 引用消息

引用的消息算作用户这条消息的一部分，和用户自己写的内容一起审核、一起判定：

- 引用的文字（`<Quoted Message>` 块）作为文字审核；
- 引用里的图片和用户自己发的图片一样审核（平台为「仅文本」时不审核图片）；
- 引用的内容违规时，整条消息被拦截，即使用户自己写的部分正常。

群聊上下文里每条历史消息中的引用摘要（`[Quote(...)]`，最长 200 字）随那条历史消息一起逐条审核，违规时只去掉那一条。

## 判定规则与可调设置

审核服务对文字给出「安全 / 有争议 / 不安全」的概率，对图片给出各档的色情（NSFW）概率。以下设置都在 `设置` → `安全` → `内容审核`，随每次审核发送，修改后立即生效：

| 设置 | 默认 | 含义 |
| --- | --- | --- |
| 文字审核阈值 | `0.9` | 不安全概率（`1 - 安全概率`，「有争议」也算在内）高于此值即判违规。调低更严：`0.5` 召回约 97%，但误判约 10% |
| 图片审核阈值 | `0.5` | 下面所选档位的概率之和高于此值即判违规 |
| 图片违规档位 | 擦边、中度、露骨 | 哪些档位算违规。取消「擦边」后泳装、内衣等擦边图不再被拦，只拦露骨图 |
| 文字拦截类别 | 全部 | 暴力、非暴力违法、色情、隐私、自残、不道德、政治敏感、版权、越狱。文字只在被判为所选类别时才拦截；模型判为不安全但没给出类别时仍会拦截 |

图片中识别出的文字按文字规则审核（受文字阈值和类别影响）；被判为色情的图片不再识别文字。

## 服务不可用时

- 文字审核超时 5 秒，带图 15 秒。
- 服务不可用（超时、5xx）：带图片的用户消息被拒绝，纯文字放行并记日志；工具结果中的图片被扣下，文字放行。
- 服务拒收（400，如图片格式不支持）：用户消息按违规处理；工具结果中被拒收的那一项被扣下。

## 长文本

审核服务一次只处理一个请求，耗时大致与 token 数成正比。为避免一段长文本拖慢其它审核，AstrBot 把文字切成不超过 16 KB 的块（相邻块重叠 512 字节）分别审核，任何一块违规即判整段违规；一次工具结果最多审核 64 KB 文字，超出部分截去并告诉模型。
